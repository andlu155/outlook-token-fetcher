# Outlook Token Fetcher

Chrome 扩展：半自动获取 Microsoft / Outlook 账号的 OAuth2 **Refresh Token**（PKCE + `nativeclient` 回调）。

支持自动模式与逐步骤模式、多固定备用邮箱轮流、自动接码、暂停/继续/下一账号、异常页恢复，以及侧栏结果排序、复制与手动导出。

> **用途说明**：仅供你有权操作的账号使用（自有账号、已授权测试环境）。请遵守 Microsoft 服务条款与当地法律。

## 功能

| 能力 | 说明 |
|------|------|
| OAuth2 PKCE | 打开授权页 → 登录/验证 → 捕获 `code` → 换取 `refresh_token` |
| 自动 / 逐步骤 | 全自动跑 1–4 步，或手动点步骤圆圈执行 |
| 备用邮箱 | 固定列表（最多 100 个，按顺序轮流）或随机本地部分 + 域名 |
| 自动接码 | 可选对接自建临时邮箱 Admin API 拉取验证码；取码前等待 3 秒，降低取到旧码概率；取码过程单飞，避免重复查询 |
| 页面识别 | 登录、备用邮箱绑定/再验证、验证码、代码发送方式（风控选通道）、失效码、通行密钥取消、保持登录、同意、帐户锁定、人机验证提示等 |
| 批处理控制 | 暂停/继续（保留队列）；停止清空队列；**下一账号**强制切到队列下一号；异常关闭后自动暂停，重开侧栏可继续 |
| 网络代理 | 可选 HTTP / SOCKS5 系统代理；支持测速与出口 IP/地区；普通/无痕上下文分 scope 应用 |
| 缓存清理 | 每处理 5 个账号自动清理 Outlook/Microsoft 登录相关缓存 |
| 异常恢复 | SSL/代理等硬网络错误直接跳过当前账号；**密码错误 / 密码登录不可用 / 登录次数过多** 直接跳过并进入下一账号；**Too Many Requests / 请求过多** 限流页直接跳过；帐户锁定 / 人机验证 /「请稍后重试」跳过；软白屏有限恢复 + 整任务重跑 1 次；登录过渡页忽略误判白屏 |
| 结果 | 侧栏展示并持久化（侧栏/窗口关闭后仍可恢复）；可按 **执行先后** 或 **状态分组** 排序；复制 / 复制成功 / 手动导出；**清空结果**；**重跑失败**（保留已成功） |
| 账号预检 | 粘贴时即时检查格式/重复；开始时跳过无效行并写日志 |
| 数据清理 | 侧栏清空结果；设置页可清空敏感配置（接码/代理密码等）或全部清空 |
| 权限 | 默认仅 Microsoft 相关域名 + 测速站；接码 API / 代理认证按需申请 optional 主机权限 |
| 日志脱敏 | 验证码、长 token 类字符串在侧栏日志中脱敏 |

## 安装（开发者模式）

1. 打开 Chrome → `chrome://extensions`
2. 开启 **开发者模式**
3. **加载已解压的扩展程序** → 选择本仓库的 [`chrome-extension`](chrome-extension) 目录
4. 固定扩展，打开 **侧边栏（Side Panel）** 使用
5. 在扩展 **选项** 中配置备用邮箱与（可选）接码 API

也可从 [Releases](https://github.com/andlu155/outlook-token-fetcher/releases) 下载 zip，解压后按同样方式加载。

升级后请在 `chrome://extensions` 点击 **重新加载**。

## 使用流程

1. **设置**
   - 固定备用邮箱：每行一个，最多 100 个；处理账号时按列表顺序循环使用
   - 或随机模式：填写邮箱域名
   - 可选：启用自动接码并填写 API 地址与 Admin 密码
   - 可选：勾选「启用代理」并填写 HTTP/SOCKS5 地址后保存（可先测速）
2. **侧栏**粘贴账号列表（常见格式：`邮箱----密码` 或按界面提示的多字段格式）
3. 选择 **自动** 或 **逐步骤**，点击开始
4. 按页面提示完成验证；成功后结果出现在侧栏，可切换排序后复制或导出
5. 若侧栏/窗口异常关闭：重新打开侧栏可看到已暂停状态与历史结果，点 **继续** 恢复

### 步骤含义

| 步骤 | 作用 |
|------|------|
| 1 | 打开 / 重开 OAuth 授权页 |
| 2 | 填写账号密码并继续 |
| 3 | 备用邮箱绑定 / 代码发送方式点下一步 / 填验证码（可多次） |
| 4 | 用授权码换取 Refresh Token |

备用邮箱验证成功后（含「旧验证码已失效」类提示），自动模式会重开授权页以完成令牌流程。

### 批处理按钮

| 按钮 | 作用 |
|------|------|
| 暂停 / 继续 | 暂停保留当前账号与队列；继续从暂停处恢复 |
| 停止 | 完全停止并清空队列 |
| 跳过步骤 | 跳过当前页面上的一步自动化 |
| 下一个账号 | 放弃当前账号，切换到队列中的下一个 |

## 接码 API（可选）

扩展会请求：

```http
GET {apiUrl}/admin/mails?limit=...&offset=...
Header: x-admin-auth: {adminPassword}
```

调用后会先等待约 **3 秒** 再开始轮询（最多约 20 次、间隔 3 秒），减少取到上一封邮件旧验证码的情况。

需自行部署兼容的临时邮箱后台；扩展不附带服务端。

## 权限说明

| 权限 | 用途 |
|------|------|
| `storage` | 队列、设置、运行状态与结果持久化 |
| `tabs` / `scripting` | 打开授权页、注入/通信 content script |
| `sidePanel` | 侧栏控制台 |
| `browsingData` / `cookies` | 周期性清理 Microsoft 登录缓存 |
| `webNavigation` | 辅助导航与异常页检测 |
| `proxy` / `webRequest` / `webRequestAuthProvider` | 可选系统代理与代理认证 |
| `declarativeNetRequest` | 辅助请求处理（如清单中已配置） |
| 主机权限 | 默认 Microsoft / Office / 测速相关域名；接码 API 与宽域代理认证为 **optional**，首次使用时申请 |

## 版本

以 [`chrome-extension/manifest.json`](chrome-extension/manifest.json) 中的 `version` 为准（当前 **1.30**）。

### 近期变更摘要

- **1.30** — 代理逻辑重构：修补代理清除与敏感配置清理未恢复系统代理隐患；选项页添加紧急一键恢复系统网络按钮
- **1.29** — 中期/长期：`shared/` 模块化 + ES module SW；`chrome.alarms` 关键调度；可配置节奏；Client ID 池与失败轮换；本批统计面板；接码适配器抽象；`npm test` 纯函数单测
- **1.28** — 短期加固：收窄 host 权限 + 扩展图标；账号预检；失败一键重跑；结果/敏感配置一键清空；日志脱敏；接码 API optional 权限；去掉外链字体
- **1.27** — HTTP/SOCKS5 代理（启用/测速/出口地区；无痕分 scope）；固定备用邮箱上限 10→100；处理结果持久化；窗口/登录页异常关闭后自动暂停，点「继续」恢复队列
- **1.26** — 识别 Microsoft「Too Many Requests / 请求过多」限流页，标记失败并跳过当前账号（不再当白屏反复重开）
- **1.25** — 验证码取码单飞：取码进行中忽略 MutationObserver 重入，避免「查询/等 3 秒/匹配到」日志成对重复
- **1.24** — 密码页失败自动跳过：识别「密码登录不可用」「帐户或密码不正确 / 登录次数过多」等，标记失败并进入下一账号；业务逻辑基于 1.23
- **1.23** — 验证码取码前等待 3 秒，降低旧码误填
- **1.22** — 处理结果支持「执行先后 / 状态分组」排序
- **1.21** — SSL 等硬网络错误直接跳过账号（不再无意义重开授权页）
- **1.20** — 识别「代码发送方式」风控页并自动点下一步
- **1.19 及更早** — 多账号批处理、下一账号、每 5 账号清缓存、白屏/卡住恢复、验证码填写加固等

完整历史见 Git 提交与 [Releases](https://github.com/andlu155/outlook-token-fetcher/releases)。
